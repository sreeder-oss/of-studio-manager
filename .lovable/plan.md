

# Cloud Migration: Schema, Auth, and Data Layer

## Summary

Enable Lovable Cloud, apply your provided schema (7 tables), set up Google sign-in, add `user_id` columns with RLS policies so each user sees only their own data, and replace the localStorage service layer with Supabase queries.

## Schema

Your schema is solid. Two additions needed:

1. **`user_id uuid` column on every table** -- references `auth.users(id)`, required for RLS so each user's data is isolated.
2. **`documents` and `photos` tables** are new -- the app doesn't have UI for these yet. We'll create the tables now; UI can come later.

Your `receipts.tax_year` generated column and `tax_deductible` boolean are great -- we'll surface those in the UI.

## Plan

### 1. Enable Lovable Cloud and Google Auth
- Enable Lovable Cloud (spins up Supabase automatically)
- Enable Google sign-in in Cloud settings
- No user profiles table needed -- we'll use `auth.users` directly for now

### 2. Run Migration: Create All Tables
- Apply your schema with `user_id uuid not null default auth.uid()` added to every table
- Enable RLS on all tables
- Add RLS policies: each user can SELECT, INSERT, UPDATE, DELETE only rows where `user_id = auth.uid()`

```text
contacts ─┬── projects ─┬── estimates
           │              ├── invoices
           │              ├── receipts
           │              ├── documents
           │              └── photos
           └── (direct refs from estimates/invoices)
```

### 3. Create Auth Pages
- Build a `/login` page with Google sign-in button
- Add an auth context provider wrapping the app
- Redirect unauthenticated users to `/login`
- Show user avatar + sign-out in the nav

### 4. Update TypeScript Types
- Align `src/types/index.ts` with the new schema (add `Project.address`, `Project.start_date`, `Project.end_date`, `Project.contract_value`; update status enums to match DB constraints; add `Document` and `Photo` interfaces; add `tax_deductible`/`tax_year` to Receipt; update Estimate fields like `valid_until`, `subtotal`, `total`, remove `number`)
- Remove `color` from Project (not in your schema)

### 5. Replace localStorage with Supabase Client
- Delete `src/services/storage.ts`
- Create `src/integrations/supabase/client.ts` (auto-generated by Lovable Cloud)
- Create React Query hooks in `src/hooks/` for each entity (useContacts, useProjects, useEstimates, useInvoices, useReceipts)
- Each hook provides `query` (list/get) and `mutation` (create/update/delete) using `@tanstack/react-query`

### 6. Update All Pages
- **Contacts, ContactDetail** -- swap `getContacts()`/`saveContact()` for `useContacts()` hook
- **Estimates, EstimateCreate, EstimateDetail** -- swap for `useEstimates()` hook; add `project_id` picker
- **Invoices, InvoiceDetail** -- swap for `useInvoices()` hook
- **Receipts** -- swap for `useReceipts()` hook; receipt image upload goes to Supabase Storage bucket
- **Dashboard/Index** -- queries from Supabase instead of localStorage

### 7. Storage Bucket for Receipt Images
- Create a `receipts` storage bucket in Supabase
- Upload receipt photos to the bucket, store the public URL in `receipts.image_url`
- RLS on the bucket: authenticated users can upload/read their own files
